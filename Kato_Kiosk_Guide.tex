\section*{How to use this guide}
\markright{How to use this guide}

installation}, from building the machine to locking it down. It is split
by who does the work:

\begin{wkwarn}[The machine must be built first]
FreedomPay FCC and the PAL packages must be installed and verified on the
machine before the kiosk goes live. IT do this once per machine: the Part~2
setup script does it as its first step, or by hand with
Appendices~\ref{sec:fcc} and~\ref{sec:pal}. Do not clear the prep checks in Part~1
until it is done.
\end{wkwarn}

\begin{wkinfo}[Golden rules]
\begin{itemize}
  \item The \textbf{API key is shown once}. IT generate it at the moment
        of install and paste it into the setup script or install command.
        It is never saved or sent anywhere. If it is lost, generate a new one.
  \item The \textbf{Kiosk ID} and the \textbf{Workstation ID} are
        different things (\S\ref{sec:ids}).
  \item Do not clear a prep check you have not checked yourself. The
        prep checks stop a half-built kiosk from going live.
\end{itemize}
\end{wkinfo}

\wkrolesection{How configuration resolves}{Account Manager}\label{sec:hierarchy}

Configuration is layered. An individual kiosk should carry the
\textbf{minimum configuration needed}: only the things unique to that
kiosk. Everything else resolves down from the levels above it.

\begin{figure}[H]
\centering
\begin{tikzpicture}[
  lvl/.style={rounded corners=2.5pt,draw=weknowazure60,
              minimum height=8mm,align=center,inner xsep=4pt,
              font=\scriptsize,text=weknownight},

  \node[lvl,fill=weknowgreyL]    (g)  {Global};
  \node[lvl,fill=weknowazure20,right=of g]  (co) {Country};
  \node[lvl,fill=weknowazure20,right=of co] (re) {Region\\(State)};
  \node[lvl,fill=weknowazure40,right=of re] (ci) {City};
  \node[lvl,fill=weknowazure40,right=of ci] (lg) {Location\\Group};
  \node[lvl,fill=weknowazure60,right=of lg] (lo) {Location};
  \node[lvl,fill=weknowazure60,right=of lo] (kg) {Kiosk\\Group};
  \node[lvl,fill=weknowazure80,right=of kg] (ki) {Kiosk};

  \draw[-{Stealth[length=2.4mm]},thick,weknowazure]

       {widest scope \quad$\longrightarrow$\quad most specific (highest priority)};
\end{tikzpicture}
\caption{The configuration hierarchy. Anything set further right overrides the same parameter set further left.}
\end{figure}

\subsection{The rule}

A parameter set at a \textbf{more granular} level overrides the same
parameter set at a \textbf{wider} level. So a currency set on a Country
applies to every location in it, until a specific Location or a single
Kiosk sets its own.

\begin{wkinfo}[Set each parameter at the widest level where it holds true]
If every kiosk in a country shares a currency, set it once on the Country;
do not repeat it on each kiosk. A repeated value does no harm at first,
but later changes miss it: you update the Country and the kiosk keeps its
own old value.
\end{wkinfo}

\subsection{When a kiosk is in more than one group}\label{sec:groupsorder}

A kiosk can belong to \textbf{several kiosk groups at once}. Assign them
on the kiosk's \textbf{Edit} tab, under \textbf{Group assignments}. A
location can likewise belong to several location groups, and both tiers
follow the same rule below.

Assigned groups carry a \textbf{display order}, and that order decides
conflicts: where two of a kiosk's groups set the same parameter, the group
\textbf{lower in the list wins} and overrides the ones above it. The list
runs widest first, like the hierarchy above, and later beats earlier. So
the most specific group goes at the bottom of the list, not the top.

\begin{wkinfo}[Put the groups in the right order]
Put the most specific group at the bottom. A kiosk that is both
\emph{eSIM-only} and part of a wider \emph{Heathrow} group should carry
the narrower group below the broader one, so the narrow group's settings
are the ones that survive.

A newly assigned group is added at the bottom, which makes it the winner
by default. If you assign a broad group after a narrow one, move it up.
\end{wkinfo}

\begin{wkwarn}[The screen does not tell you which end wins]
The rows show only an order number. Nothing on the panel says whether the
top or the bottom takes precedence, so after any reorder confirm the
outcome on the kiosk's \textbf{Resolved} tab rather than trusting the
list.
\end{wkwarn}

\subsection{Working out where a parameter belongs}

Ask how widely the value is true, and set it at that level:

\begin{center}
\renewcommand{\arraystretch}{1.35}\small
\begin{tabularx}{\textwidth}{L{34mm} X}
\rowcolor{weknownight}\color{white}\textbf{Level} &
\color{white}\textbf{Typically carries}\\
Global &
Anything true of every WeKnow kiosk everywhere. Rarely touched.\\
\rowcolor{weknowgreyL}
Country &
Things that follow the market: currency, tax treatment, default
language.\\
Region (State) &
Regional variations within a country, where they exist.\\
\rowcolor{weknowgreyL}
City &
Things that follow geography: relevant airports, default Uber
suggestions.\\
Location Group &
A set of sites treated the same, e.g.\ one hotel brand or one operator
across several properties.\\
\rowcolor{weknowgreyL}
Location &
The property itself: hotel name, address, tax entity, banking details.\\
Kiosk Group &
A set of kiosks that share a specific configuration. \textbf{Not limited
to one location}: a kiosk group can span sites, e.g.\ every Uber-only,
HEx-only or eSIM-only kiosk across the estate. Also used for kiosks
treated the same within a single site.\\
\rowcolor{weknowgreyL}
Kiosk &
Only what is unique to the single machine.\\
\end{tabularx}
\end{center}

The right-hand column is a guide, not a fixed rule. Many parameters can be
set at more than one level. Pick the widest level that is still correct.

\begin{wkinfo}[Check what a kiosk ends up with]
The kiosk's \textbf{Resolved} tab shows the effective configuration after
the whole hierarchy has been applied. Use it to confirm a kiosk is picking
up what you intended, and to find the old override when it is not.
\end{wkinfo}

% 3  PART 1 -- COMMAND CENTRE

\wkrolesection{Part 1: Command Centre}{Account Manager}\label{sec:part1}

Done from any machine with a browser. You are creating and configuring the
kiosk record, clearing its prep checks, scheduling the installation, and
sending IT a link to the kiosk. You do \textbf{not} generate the API key.
IT do that at install time.

\subsection{Create the location and the kiosk}

\begin{enumerate}
  \item Open \href{https://command.weknow.technology}{Command Centre}
        and sign in. Ask the WKG Technology team if you do not have an
        account.

  \item Go to \href{https://command.weknow.technology/locations}{Locations}
        and create the location, working down the hierarchy:
        \textbf{Country $\rightarrow$ Region $\rightarrow$ City
        $\rightarrow$ Location}. Open it and \textbf{copy the Location
        ID}. You need it when you create the installation record.
\end{enumerate}

\screenshot[0.50]{cc-location-id}{The location Overview tab. Use the copy icon next to \textbf{Location ID}.}

\begin{enumerate}\setcounter{enumi}{2}
  \item \emph{Only if required:} create a group from
        \href{https://command.weknow.technology/groups}{Groups}. Groups
        apply shared configuration to several sites or several kiosks at
        once:
    \begin{itemize}
      \item \textbf{Location groups}: sites treated the same, e.g.\ one
            hotel brand or one operator across several properties.
      \item \textbf{Kiosk groups}: kiosks that share a specific
            configuration. These are \emph{not} limited to a single
            location: a kiosk group can gather every Uber-only, HEx-only
            or eSIM-only kiosk across different sites.
    \end{itemize}
    Skip this for a single standalone kiosk.

  \item Go to \textbf{Kiosks} and select \textbf{Add Kiosk}:
    \begin{itemize}
      \item \textbf{Name}: what the team calls the kiosk,
            e.g.\ \emph{T2/T3 Tunnel - 2}.
      \item \textbf{Serial number}: the workstation label,
            e.g.\ \wpath{WKG-POS-617}.
      \item \textbf{Hardware model}, e.g.\ \emph{K10/20}.
      \item \textbf{Firmware version}, e.g.\ \emph{1.0.0}.
    \end{itemize}
    Then select \textbf{Create Kiosk}.
\end{enumerate}

\screenshot[0.42]{cc-add-kiosk}{Add Kiosk. The kiosk is created unassigned. The installation record ties it to a location.}

\begin{enumerate}\setcounter{enumi}{4}
  \item The new kiosk appears as \textbf{In Stock}. This is expected.
        It stays In Stock until it is installed.

  \item If the kiosk belongs to any kiosk groups, open its \textbf{Edit}
        tab and assign them under \textbf{Group assignments}. A kiosk can
        be in several groups at once, and their order decides which one
        wins a conflict (\S\ref{sec:groupsorder}).
\end{enumerate}

\screenshot[0.36]{cc-group-assignments}{Group assignments on the kiosk Edit tab. Pick a group and select \textbf{Assign}; assigned groups are held in a display order, widest first, and the group at the bottom wins a conflict.}

\subsection{Set the payment credentials}\label{sec:payment}

Set the FreedomPay \textbf{Store ID (StID)} and \textbf{Terminal ID
(TID)} in the kiosk configuration, so payment requests are signed for the
correct merchant.

\subsection{Clear the prep checks}

Open the kiosk and go to the \textbf{Edit} tab. Mark the prep checks
\textbf{Complete} to confirm the kiosk is ready to config and install.

\screenshot[0.74]{cc-prep-checks}{Prep checks on the kiosk Edit tab.}

Before clearing them, verify with IT that:

\begin{itemize}
  \item all the hardware is plugged in and working: printer, PDQ,
        sensors and scanners;
  \item FreedomPay has been installed, and the
        \wpath{FreewayClientService} and \wpath{FreewayServerService} are
        running (step~1 of the setup script, or Appendix~\ref{sec:fcc}).
\end{itemize}

\subsection{Create the installation record}

The installation record ties the kiosk to its location and moves it out of
\emph{In Stock}.

\begin{enumerate}
  \item Go to
        \href{https://command.weknow.technology/installations}{Installations}
        and select \textbf{Add Installation}.

  \item Complete the form:
    \begin{itemize}
      \item \textbf{Kiosk}: the kiosk you created above.
      \item \textbf{Location ID}: the UUID you copied earlier.
      \item \textbf{Planned date}: the installation date.
      \item \textbf{Hardware model} and \textbf{Serial number}: these must
            match the kiosk record.
      \item \textbf{Installer name}, \textbf{Installer contact} and
            \textbf{Installation company}.
      \item \textbf{Notes}: anything the engineer on site needs to
            know, e.g.\ \emph{``Install near main entrance''}.
    \end{itemize}

  \item Select \textbf{Create Installation}.
\end{enumerate}

\screenshot[0.36]{cc-add-installation}{Add Installation. This links the kiosk to its location and records who is installing it.}

\subsection{Send IT the kiosk link}\label{sec:handover}

Open the kiosk in Command Centre and copy the page's address from the
browser bar. Send it to IT in the install ticket or chat. The link is
\textbf{not sensitive}. IT get what they need from that page: the Kiosk
ID, the Workstation ID (the kiosk's serial number) and the API keys tab.

If the printer is on a port other than the standard \wpath{COM8}, say so
in the same message.

\begin{wkinfo}[Done when]
The kiosk record exists and is configured, its prep checks are cleared,
the installation record is created, and IT have the link to the kiosk.
\end{wkinfo}

\wkrolesection{Part 2: Install and lock the kiosk}{IT}\label{sec:part2}

You need the link to the kiosk in Command Centre from the Account Manager,
and a Command Centre account. Ask the WKG Technology team if you do not
have one.

There are two ways to do this part. Use \textbf{Option A}. Use Option~B
only if the script cannot be used, or to finish by hand a job the script
stopped on.

\begin{center}
\renewcommand{\arraystretch}{1.35}\small
\begin{tabularx}{\textwidth}{L{44mm} X}
\rowcolor{weknownight}\color{white}\textbf{Option} &
\color{white}\textbf{What it does}\\
A: Setup script from N-central (\S\ref{sec:ncentral}) &
One paste into the N-central remote connection. It builds the machine
(Appendices~\ref{sec:fcc} and~\ref{sec:pal}), installs the Kato app, locks the machine into
kiosk mode and restarts it into Kato, checking each result as it goes.\\
\rowcolor{weknowgreyL}
B: By hand (\S\ref{sec:manual}) &
Appendix~\ref{sec:manualapp}: FreedomPay and PAL flashing, then the
silent install signed in as \wpath{SelfBooker}, then the shell lock with

\end{tabularx}
\end{center}

\subsection{Before you install}\label{sec:preinstall}

\begin{itemize}
  \item The \textbf{PDQ is plugged in}. The build cannot be verified
        without it.
  \item You know the kiosk's \textbf{region}: \wpath{UK}, \wpath{DE},
        \wpath{ES} or \wpath{PT}. It picks the FreedomPay config and PAL
        package.
  \item \wpath{SelfBooker} is \textbf{signed in}, or \textbf{signs in
        automatically} when the machine starts. The script installs the
        app as \wpath{SelfBooker} either way.
  \item For Option~A: the machine's \textbf{computer name is its
        Workstation ID}, e.g.\ \wpath{WKG-POS-617}. This is the kiosk's
        serial number in Command Centre. The script uses the computer name as the
        Workstation ID. If they differ, use Option~B, where you type the
        Workstation ID yourself.
\end{itemize}

\subsection{Get the Kiosk ID and API key}\label{sec:getkeys}

Do this \textbf{immediately before you install}, with the setup script or
install command open and ready to paste into.

\begin{enumerate}
  \item Open the kiosk link from the Account Manager. On the
        \textbf{Overview} tab, \textbf{copy the Kiosk ID}. The kiosk's
        \textbf{serial number} is the Workstation ID.
\end{enumerate}

\screenshot[0.48]{cc-kiosk-id}{Kiosk Overview. Copy the \textbf{Kiosk ID}.}

\begin{enumerate}\setcounter{enumi}{1}
  \item Switch to the \textbf{API keys} tab and select \textbf{Generate
        API key}. This is the key the kiosk uses to authenticate to the
        server.
\end{enumerate}

\screenshot[0.46]{cc-api-key}{Kiosk API keys. Generate the key here.}

\begin{wkwarn}[Use the API key at once and do not save it]
The full key is displayed \textbf{only once, at creation}. Paste it
directly into the setup script or install command. Do not save it anywhere
or send it to anyone: not in the ticket, chat, email or a notes file. If
you lose it before the install is done, generate a new one.
\end{wkwarn}

\subsection{Option A: Setup script from N-central}\label{sec:ncentral}

The setup script, \wpath{setup\_kiosk.ps1}, runs in the N-central remote
connection's PowerShell, as the machine's system account. It holds three
steps and runs them in order, stopping at the first one that fails.

\begin{enumerate}
  \item Open the N-central remote connection to the machine. In the
        \textbf{System Shell} panel, select the \textbf{PowerShell} icon at
        the top right to switch the shell to PowerShell mode.
\end{enumerate}

\screenshot[0.94]{ncentral-powershell}{N-central System Shell. The PowerShell icon is the first of the three at the top right; the shell shows \textbf{Powershell} once switched.}

\begin{enumerate}\setcounter{enumi}{1}
  \item On your own computer, open the script with the button below. It
        opens as text in the browser. Select all (\textbf{Ctrl+A}), copy
        (\textbf{Ctrl+C}) and paste it into a new \textbf{Notepad} window.
        \begin{center}
        \href{https://raw.githubusercontent.com/vedant-kalbag-wkg/kato-installation-guide/main/scripts/v2/setup_kiosk.ps1}{%
          \colorbox{weknowazure}{\color{white}\bfseries\strut\quad Open setup\_kiosk.ps1\quad}}
        \end{center}
  \item In Notepad, replace the three values at the top
        (\wpath{\$Region}, \wpath{\$KioskId} and \wpath{\$ApiKey}) with
        the region and the values from \S\ref{sec:getkeys}. Keep the
        quotes, and do not change anything below them. If a value is

\paragraph{Restart the FCC services and wait for \emph{Lane Open}.}

Windows names are \wpath{FCCServerSvc} and \wpath{FCCClientSvc}. The
command shows the service status. Then it monitors the FCC log for up to
60 seconds.

\begin{lstlisting}

\subsection{Finding the printer's COM port}\label{sec:comport}

\begin{wkwarn}[Do not use Device Manager for this]
Kato sends data \textbf{directly to the COM port}. There is no printer
driver. The port that Device Manager shows is \emph{not} always the port
that the printer uses. Get the list of ports, then test each port.
\end{wkwarn}

\paragraph{1. Get the list of ports.} In PowerShell:

\begin{lstlisting}
# Only the port names
[System.IO.Ports.SerialPort]::GetPortNames()

# The port names with the device names
$ports = Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match 'COM\d+' }
$ports | Select-Object Name, DeviceID
\end{lstlisting}

\noindent In Command Prompt (\textbf{CMD} mode in the N-central shell),
\wpath{mode} shows all COM devices and their settings:

\begin{lstlisting}
mode
\end{lstlisting}

\paragraph{2. Test each port.} Send data to one port at a time. When you
find the correct port, the printer prints some lines of random characters.
Run these commands in \textbf{Command Prompt}. Use the ports from step~1:

\begin{lstlisting}
DIR > COM3
DIR > COM4
DIR > COM8
\end{lstlisting}

\noindent In PowerShell, use \wpath{cmd} to send the data. If you do not, PowerShell
makes a file:

\begin{lstlisting}
cmd /c "DIR > COM8"
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.3}\small
\begin{tabularx}{\textwidth}{L{54mm} X}
\rowcolor{weknownight}\color{white}\textbf{Result} &
\color{white}\textbf{What it means}\\
The printer prints random characters &
This is the correct port. Write it down. Go to step~3.\\
\rowcolor{weknowgreyL}
The command stops, and the printer does not print &
The port is there, but the printer is not on it. Try the next port.\\
\emph{Access is denied} &
A program uses the port. This is usually Kato. Close Kato and try
again.\\
\rowcolor{weknowgreyL}
\emph{The system cannot find the path specified} &
The port is not there. Try the next port.\\
\end{tabularx}
\end{center}

\paragraph{3. Set the port in \wpath{kiosk-identity.json}.} You do
\textbf{not} have to install Kato again. Open
\wpath{kiosk-identity.json}. Set the printer port to the correct port and
save the file. Then push \textbf{Ctrl+Shift+R+L} to restart Kato, and print a test
receipt.

\begin{wkinfo}[Write the port on the installation record]
If the printer uses an unusual port, write it in the \textbf{Notes} field
of the installation record. This helps the next engineer.
\end{wkinfo}

\subsubsection{Push a file to kiosks from N-central}\label{sec:filepush}

Use this to add or replace a file on one or more kiosks, such as a new
installer or an updated config. There are two ways, and neither needs a
remote session.

\paragraph{Option 1: File Transfer task (upload the file each time).}
This task is not on a single device's \textbf{Add Task} menu; it is
created at Customer or Service Organization level.
\begin{enumerate}
  \item In N-central, select the \textbf{customer} (not a site or
        device), then \textbf{Configuration $\rightarrow$ Scheduled Tasks
        $\rightarrow$ Add/Delete $\rightarrow$ Add $\rightarrow$ File
        Transfer}. If it is missing, your role needs the
        \textbf{Scheduled Tasks} permission.
  \item Choose \textbf{Use LocalSystem Credentials}, \textbf{Browse} to
        the file (under 500\,MB), and set \textbf{Remote Location} to the
        destination folder, e.g.\
        \wpath{C:\textbackslash Users\textbackslash SelfBooker\textbackslash Documents}.
        Turn on the \textbf{overwrite} option to replace an older copy.
  \item On \textbf{Targets}, tick every kiosk that needs the file.
  \item On \textbf{Schedule}, run it now, then \textbf{Save}. Check each
        kiosk under \textbf{Reports $\rightarrow$ Status $\rightarrow$
        Scheduled Tasks Summary}.
\end{enumerate}
When the file is updated, add a new task with the new file.

\paragraph{Option 2: Download script (update the file in one place).}
Host the file at an HTTPS link the kiosks can reach (e.g.\ a SharePoint
or Azure storage download link) and keep that link the same when the
file changes. \wpath{Get-KioskFile.ps1} downloads it onto each kiosk and
replaces any older copy.
\begin{enumerate}
  \item Once: add \wpath{scripts/Get-KioskFile.ps1} from the guide's
        repository to \textbf{Script/Software Repository $\rightarrow$
        Add $\rightarrow$ Scripting}.
  \item At customer level, \textbf{Configuration $\rightarrow$ Scheduled
        Tasks $\rightarrow$ Add/Delete $\rightarrow$ Add $\rightarrow$
        Scripting}: choose the script, \textbf{LocalSystem}, and the
        command-line parameters\\
        \wpath{-Url '<https link>' -Destination '<folder>'}\\
        (add \wpath{-FileName '<name>'} if the link does not end in the
        file name).
  \item Tick the kiosks on \textbf{Targets} and run it now. Each kiosk
        reports \texttt{=== SUCCESS ===} with the file's SHA256, which
        should match on every kiosk.
\end{enumerate}
When the file is updated, replace it at the link and re-run the task.

\subsection{Shell lock}\label{sec:lockdown}

The Shell Launcher utility replaces the Windows desktop with the Kato app
for the \wpath{SelfBooker} account. The machine starts in the kiosk app,
and there is no desktop to get out to. Step~3 of the setup script
does the same thing.

\begin{enumerate}
  \item Signed in as \wpath{WKGAdmin}, run\\
        \wpath{C:\textbackslash Kiosk\textbackslash SSM25\_files\textbackslash Shell-Launcher-Utilities\textbackslash SLUtility.exe}

  \item Select \textbf{Disable User Shell}.

  \item \textbf{Close and reopen} \wpath{SLUtility}. It only sees the
        change after a restart. Do not skip this.

  \item Select the \wpath{SelfBooker} user and change the shell path to
        the app, leaving the default \textbf{Action 3}:\\
        \wpath{C:\textbackslash Users\textbackslash SelfBooker\textbackslash AppData\textbackslash Local\textbackslash Programs\textbackslash Kiosk\textbackslash Kiosk.exe}

  \item Select \textbf{Set User Shell}.

  \item Select \textbf{Enable Shell Launcher}.

  \item Sign out of \wpath{WKGAdmin} and sign in as \wpath{SelfBooker}.
        The Kato app should launch full screen with no desktop behind it.
        Reboot once to confirm it comes back the same way.
\end{enumerate}

\begin{wkwarn}[Order matters]
Disable $\rightarrow$ restart the utility $\rightarrow$ set the path
$\rightarrow$ set shell $\rightarrow$ enable. Do not set the shell before
restarting \wpath{SLUtility}.
\end{wkwarn}

\begin{wkinfo}[Done when]
The machine restarts into the Kato app as \wpath{SelfBooker}, with
no visible desktop, taskbar or file explorer. Blank screen for over
2 minutes? See \S\ref{sec:blank}.
\end{wkinfo}
