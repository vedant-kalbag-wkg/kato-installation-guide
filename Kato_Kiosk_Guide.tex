installation}, from building the machine to locking it down. It is split
by who does the work:

\begin{wkwarn}[The machine must be built first]
FreedomPay FCC and the PAL packages must be installed and verified on the
machine before the kiosk goes live. IT do this once per machine using
Appendix~\ref{sec:fcc} --- the prep checks in Part~1 cannot honestly be
cleared until it is done.
\end{wkwarn}

\begin{wkinfo}[Golden rules]
\begin{itemize}
  \item The \textbf{API key is shown once}. IT generate it at the moment
        of install and paste it straight into the install --- it is never
        saved or sent anywhere. If it is lost, generate a new one.
  \item The \textbf{Kiosk ID} and the \textbf{Workstation ID} are
        different things --- see \S\ref{sec:ids}.
  \item Do not clear a prep check you have not actually verified. It is
        the only thing standing between a half-built kiosk and a live
        one.
\end{itemize}
\end{wkinfo}

\wkrolesection{How configuration resolves}{Account Manager}\label{sec:hierarchy}

Configuration is layered. An individual kiosk should carry the
\textbf{minimum configuration needed} --- only the things genuinely unique
to that kiosk. Everything else resolves down from the levels above it.

\begin{figure}[H]
\centering

  \node[lvl,fill=weknowazure40,right=of re] (ci) {City};
  \node[lvl,fill=weknowazure40,right=of ci] (lg) {Location\\Group};
  \node[lvl,fill=weknowazure60,right=of lg] (lo) {Location};

  \node[lvl,fill=weknowazure80,right=of kg] (ki) {Kiosk};

\end{figure}

\subsection{The rule}

A parameter set at a \textbf{more granular} level overrides the same
parameter set at a \textbf{wider} level. So a currency set on a Country
applies to every location in it, until a specific Location --- or a single
Kiosk --- sets its own.

\begin{wkinfo}[Set each parameter at the widest level where it holds true]
If every kiosk in a country shares a currency, set it once on the Country;
do not repeat it on each kiosk. Repeating a value further down does no
harm on day one, but it is the thing that makes later changes miss ---
you update the Country and the kiosk keeps its own stale override.
\end{wkinfo}

\subsection{When a kiosk is in more than one group}\label{sec:groupsorder}

A kiosk can belong to \textbf{several kiosk groups at once}. Assign them
on the kiosk's \textbf{Edit} tab, under \textbf{Group assignments}. A
location can likewise belong to several location groups, and both tiers
follow the same rule below.

Assigned groups carry a \textbf{display order}, and that order decides
conflicts: where two of a kiosk's groups set the same parameter, the group
\textbf{lower in the list wins} and overrides the ones above it. The list
runs widest first, exactly like the hierarchy above it --- later beats
earlier --- so the bottom of the list is the most specific position, not
the top.

\begin{wkinfo}[Order the groups deliberately]
Put the most specific group at the bottom. A kiosk that is both
\emph{eSIM-only} and part of a wider \emph{Heathrow} group should carry
the narrower group below the broader one, so the narrow group's settings
are the ones that survive.

A newly assigned group is added at the bottom, which makes it the winner
by default. If you assign a broad group after a narrow one, move it up.
\end{wkinfo}

\begin{wkwarn}[The screen does not tell you which end wins]
The rows show only an order number. Nothing on the panel says whether the
top or the bottom takes precedence, so after any reorder confirm the
outcome on the kiosk's \textbf{Resolved} tab rather than trusting the
list.
\end{wkwarn}

\subsection{Working out where a parameter belongs}

Ask how widely the value is true, and set it at that level:

\begin{center}
\renewcommand{\arraystretch}{1.35}\small
\begin{tabularx}{\textwidth}{L{34mm} X}
\rowcolor{weknownight}\color{white}\textbf{Level} &
\color{white}\textbf{Typically carries}\\
Global &
Anything true of every WeKnow kiosk everywhere. Rarely touched.\\
\rowcolor{weknowgreyL}
Country &
Things that follow the market --- currency, tax treatment, default
language.\\
Region (State) &
Regional variations within a country, where they exist.\\
\rowcolor{weknowgreyL}
City &
Things that follow geography --- relevant airports, default Uber
suggestions.\\
Location Group &
A set of sites treated the same, e.g.\ one hotel brand or one operator
across several properties.\\
\rowcolor{weknowgreyL}
Location &
The property itself --- hotel name, address, tax entity, banking details.\\
Kiosk Group &
A set of kiosks that share a specific configuration. \textbf{Not limited
to one location} --- a kiosk group can span sites, e.g.\ every Uber-only,
HEx-only or eSIM-only kiosk across the estate. Also used for kiosks
treated the same within a single site.\\
\rowcolor{weknowgreyL}
Kiosk &
Only what is unique to the single machine.\\
\end{tabularx}
\end{center}

The right-hand column is a guide to intent, not a fixed schema --- many
parameters can legitimately be set at more than one level. What matters is
choosing the widest one that is still correct.

\begin{wkinfo}[Check what a kiosk actually ends up with]
The kiosk's \textbf{Resolved} tab shows the effective configuration after
the whole hierarchy has been applied. Use it to confirm a kiosk is picking
up what you intended --- and to find the stale override when it is not.
\end{wkinfo}

% 3  PART 1 -- COMMAND CENTRE

\wkrolesection{Part 1 --- Command Centre}{Account Manager}\label{sec:part1}

Done from any machine with a browser. You are creating and configuring the
kiosk record, clearing its prep checks, scheduling the installation, and
sending IT a link to the kiosk. You do \textbf{not} generate the API key ---
IT do that at install time.

\subsection{Create the location and the kiosk}

\begin{enumerate}
  \item Open \href{https://command.weknow.technology}{Command Centre}
        and sign in. Ask the WKG Technology team if you do not have an
        account.

  \item Go to \href{https://command.weknow.technology/locations}{Locations}
        and create the location, working down the hierarchy:
        \textbf{Country $\rightarrow$ Region $\rightarrow$ City
        $\rightarrow$ Location}. Open it and \textbf{copy the Location
        ID} --- you need it when you create the installation record.
\end{enumerate}

\screenshot[0.50]{cc-location-id}{The location Overview tab. Use the copy icon next to \textbf{Location ID}.}

\begin{enumerate}\setcounter{enumi}{2}
  \item \emph{Only if required:} create a group from
        \href{https://command.weknow.technology/groups}{Groups}. Groups
        apply shared configuration to several sites or several kiosks at
        once:
    \begin{itemize}
      \item \textbf{Location groups} --- sites treated the same, e.g.\ one
            hotel brand or one operator across several properties.
      \item \textbf{Kiosk groups} --- kiosks that share a specific
            configuration. These are \emph{not} limited to a single
            location: a kiosk group can gather every Uber-only, HEx-only
            or eSIM-only kiosk across different sites.
    \end{itemize}
    Skip this for a single standalone kiosk.

  \item Go to \textbf{Kiosks} and select \textbf{Add Kiosk}:
    \begin{itemize}
      \item \textbf{Name} --- how the kiosk is referred to operationally,
            e.g.\ \emph{T2/T3 Tunnel - 2}.
      \item \textbf{Serial number} --- the workstation label,
            e.g.\ \wpath{WKG-POS-617}.
      \item \textbf{Hardware model} --- e.g.\ \emph{K10/20}.
      \item \textbf{Firmware version} --- e.g.\ \emph{1.0.0}.
    \end{itemize}
    Then select \textbf{Create Kiosk}.
\end{enumerate}

\screenshot[0.42]{cc-add-kiosk}{Add Kiosk. The kiosk is created unassigned --- it is tied to a location by the installation record.}

\begin{enumerate}\setcounter{enumi}{4}
  \item The new kiosk appears as \textbf{In Stock}. That is expected ---
        it stays In Stock until it is installed.

  \item If the kiosk belongs to any kiosk groups, open its \textbf{Edit}
        tab and assign them under \textbf{Group assignments}. A kiosk can
        be in several groups at once, and the order they sit in decides
        which one wins a conflict --- see \S\ref{sec:groupsorder}.
\end{enumerate}

\screenshot[0.36]{cc-group-assignments}{Group assignments on the kiosk Edit tab. Pick a group and select \textbf{Assign}; assigned groups are held in a display order, widest first, and the group at the bottom wins a conflict.}

\subsection{Set the payment credentials}

Set the FreedomPay \textbf{Store ID (StID)} and \textbf{Terminal ID
(TID)} in the kiosk configuration, so payment requests are signed for the
correct merchant.

\subsection{Clear the prep checks}

Open the kiosk and go to the \textbf{Edit} tab. Mark the prep checks
\textbf{Complete} to confirm the kiosk is ready to config and install.

\screenshot[0.74]{cc-prep-checks}{Prep checks on the kiosk Edit tab.}

Before clearing them, verify with IT that:

\begin{itemize}
  \item all the hardware is plugged in and working --- printer, PDQ,
        sensors and scanners;
  \item FreedomPay has been installed, and the
        \wpath{FreewayClientService} and \wpath{FreewayServerService} are
        running (Appendix~\ref{sec:fcc}).
\end{itemize}

\subsection{Create the installation record}

The installation record ties the kiosk to its location and moves it out of
\emph{In Stock}.

\begin{enumerate}
  \item Go to
        \href{https://command.weknow.technology/installations}{Installations}
        and select \textbf{Add Installation}.

  \item Complete the form:
    \begin{itemize}
      \item \textbf{Kiosk} --- the kiosk you created above.
      \item \textbf{Location ID} --- the UUID copied earlier.
      \item \textbf{Planned date} --- the installation date.
      \item \textbf{Hardware model} and \textbf{Serial number} --- must
            match the kiosk record.
      \item \textbf{Installer name}, \textbf{Installer contact} and
            \textbf{Installation company}.
      \item \textbf{Notes} --- anything the engineer on site needs to
            know, e.g.\ \emph{``Install near main entrance''}.
    \end{itemize}

  \item Select \textbf{Create Installation}.
\end{enumerate}

\screenshot[0.36]{cc-add-installation}{Add Installation --- links the kiosk to its location and records who is installing it.}

\subsection{Send IT the kiosk link}\label{sec:handover}

Open the kiosk in Command Centre and copy the page's address from the
browser bar. Send it to IT in the install ticket or chat --- the link is
\textbf{not sensitive} and needs no special handling. Everything IT need
is on that page: the Kiosk ID, the Workstation ID (the kiosk's serial
number), and the API keys tab.

If the printer is on a port other than the standard \wpath{COM8}, say so
in the same message.

\begin{wkinfo}[Done when]
The kiosk record exists and is configured, its prep checks are cleared,
the installation record is created, and IT have the link to the kiosk.
\end{wkinfo}

\wkrolesection{Part 2 --- Install and lock the kiosk}{IT}\label{sec:part2}

You need the link to the kiosk in Command Centre from the Account Manager,
and a Command Centre account --- ask the WKG Technology team if you do not
have one.

\begin{wkwarn}[Build the machine first]
If FreedomPay FCC is not yet installed and verified on this machine, do
Appendix~\ref{sec:fcc} first. It is done once per machine, signed in as
\wpath{WKGAdmin}.
\end{wkwarn}

\subsection{Get the installer onto the machine}

\begin{enumerate}
  \item Download the latest \wpath{Kiosk Setup X.Y.Z.exe} from the
        \href{https://github.com/WeKnowTechnology/wkg-electron-app/releases}{app
        releases page}.

  \item Copy it into\\
        \wpath{C:\textbackslash Users\textbackslash SelfBooker\textbackslash Documents}\\
        This is the folder the N-central script looks in. Keep only one
        installer there --- if several are present the script takes the
        highest version and warns about the rest.
\end{enumerate}

\subsection{Get the Kiosk ID and API key}\label{sec:getkeys}

Do this \textbf{immediately before you install}, with the install script or
command open and ready to paste into.

\begin{enumerate}
  \item Open the kiosk link from the Account Manager. On the
        \textbf{Overview} tab, \textbf{copy the Kiosk ID}. The kiosk's
        \textbf{serial number} is the Workstation ID.
\end{enumerate}

\screenshot[0.48]{cc-kiosk-id}{Kiosk Overview --- copy the \textbf{Kiosk ID}.}

\begin{enumerate}\setcounter{enumi}{1}
  \item Switch to the \textbf{API keys} tab and select \textbf{Generate
        API key}. This is the key the kiosk uses to authenticate to the
        server.
\end{enumerate}

\screenshot[0.46]{cc-api-key}{Kiosk API keys. Generate the key here.}

\begin{wkwarn}[Use the API key straight away --- do not save it]
The full key is displayed \textbf{only once, at creation}. Paste it
directly into the install script or command. Do not save it anywhere or
send it to anyone --- not the ticket, chat, email or a notes file. If you
lose it before the install is done, simply generate a new one.
\end{wkwarn}

Then install using \textbf{one} of the two methods below. The N-central
script is preferred: it validates the credentials, runs the install as
\wpath{SelfBooker} and checks the result for you.

\subsection{Option A --- One-run script from N-central}\label{sec:ncentral}

\begin{enumerate}
  \item Make sure \wpath{SelfBooker} is \textbf{signed in} on the machine.
        The install is per-user, and the script warns if the account is not
        logged on.

  \item Open the N-central remote connection to the machine. In the
        \textbf{System Shell} panel, select the \textbf{PowerShell} icon at
        the top right to switch the shell to PowerShell mode.
\end{enumerate}

\screenshot[0.94]{ncentral-powershell}{N-central System Shell. The PowerShell icon is the first of the three at the top right; the shell shows \textbf{Powershell} once switched.}

\begin{enumerate}\setcounter{enumi}{2}
  \item Click the button below. The script opens on GitHub in your
        browser (sign in if asked). Select \textbf{Download raw file}, the
        download icon above the script, and open the downloaded
        \wpath{Install-Kiosk.txt} in Notepad.
        \begin{center}
        \href{https://github.com/vedant-kalbag-wkg/kato-installation-guide/blob/main/scripts/Install-Kiosk.txt}{%
          \colorbox{weknowazure}{\color{white}\bfseries\strut\quad Open Install-Kiosk.txt\quad}}
        \end{center}
  \item Replace the three values at the top --- \wpath{\$KioskId},
        \wpath{\$WorkstationId} and \wpath{\$ApiKey} --- with the ones from
        \S\ref{sec:getkeys}. The script rejects the placeholders, so it
        will not run until they are replaced. Close Notepad without saving
        once the script is copied.

  \item Select all (\textbf{Ctrl+A}), copy (\textbf{Ctrl+C}), and paste
        the whole script into the N-central shell.

  \item Press \textbf{Enter twice}: once to submit the script and once to
        run it.

  \item Wait for \textbf{\texttt{=== SUCCESS ===}}. Anything else ends in
        \texttt{=== FAILED ===} with the reason on the next line.
\end{enumerate}

\begin{wkinfo}[The script does not set the printer]
It installs with the default port, \wpath{COM8}, and prints the port it
ended up with on the \texttt{Printer:} line. If the printer is elsewhere,
correct it in \wpath{kiosk-identity.json} --- see \S\ref{sec:comport}.
\end{wkinfo}

Skip to step~3 of Option~B to confirm the identity file, then continue with
the lockdown.

\subsection{Option B --- Manually, signed in as \wpath{SelfBooker}}

Done \textbf{signed in as \wpath{SelfBooker}} --- the account the kiosk
runs as.

\begin{enumerate}
  \item Sign in to Windows as \wpath{SelfBooker}.

  \item Open \textbf{PowerShell} in
        \wpath{C:\textbackslash Users\textbackslash SelfBooker\textbackslash Documents}
        and run the silent install, substituting the installer version and
        your values from \S\ref{sec:getkeys}:
\end{enumerate}

\begin{lstlisting}
& ".\Kiosk Setup X.Y.Z.exe" /S `
  /KIOSKID={KIOSK_ID_FROM_COMMAND_CENTRE} `
  /WORKSTATIONID={WKG-POS-XXX} `
  /APIKEY={API_KEY_FROM_COMMAND_CENTRE} `
  /PRINTER=COM8
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.3}\small
\begin{tabularx}{\textwidth}{L{34mm} X}
\rowcolor{weknownight}\color{white}\textbf{Switch} &
\color{white}\textbf{Value}\\
\wpath{/S} & Silent install --- no prompts. Always used.\\
\rowcolor{weknowgreyL}
\wpath{/KIOSKID} & The Kiosk ID from the kiosk's Overview tab.\\
\wpath{/WORKSTATIONID} & The machine label, e.g.\ \wpath{WKG-POS-617} ---
the kiosk's serial number.\\

\subsection{Checking \wpath{kiosk-identity.json}}\label{sec:identity}

Most \emph{will not connect} faults are in this file. Open it in Notepad
(path in \S\ref{sec:paths}). A correct file looks like this:

\begin{lstlisting}
{
  "kioskId": "{KIOSK_ID_FROM_COMMAND_CENTRE}",
  "apiBaseUrl": "https://api.weknow.technology/api",
  "apiKey": "{API_KEY_FROM_COMMAND_CENTRE}",
  "workstationId": "WKG-POS-XXX",
  "printerDestination": "COM8",
  "fleetSocketUrl": "wss://api.weknow.technology"
}
\end{lstlisting}

\begin{center}
\renewcommand{\arraystretch}{1.35}\small
\begin{tabularx}{\textwidth}{L{40mm} X}
\rowcolor{weknownight}\color{white}\textbf{Field} &
\color{white}\textbf{Check}\\
\wpath{apiBaseUrl} &
Must be \wpath{https://api.weknow.technology/api} --- \textbf{not}
\wpath{https://dev.weknow.technology/api}.\\
\rowcolor{weknowgreyL}
\wpath{fleetSocketUrl} &
Must be \wpath{wss://api.weknow.technology} --- \textbf{not}
\wpath{wss://dev.weknow.technology}.\\
\wpath{kioskId} &
Matches the Kiosk ID on the kiosk's Overview tab, and does \textbf{not end
in a backtick} (\wpath{`}).\\
\rowcolor{weknowgreyL}
\wpath{apiKey} &
Matches the key generated for this kiosk, and does \textbf{not end in a
backtick}.\\
\wpath{workstationId} &
The machine label, e.g.\ \wpath{WKG-POS-617} --- not the Kiosk ID.\\
\rowcolor{weknowgreyL}
\wpath{printerDestination} &
The printer's COM port (\S\ref{sec:comport}).\\
\end{tabularx}
\end{center}

\begin{wkwarn}[Why a backtick ends up in a value]
In the manual install command, each line ends in a backtick to continue
it. If a space follows the backtick, or the command is pasted onto one
line, PowerShell passes the backtick through as part of the value. Delete
it from the file.
\end{wkwarn}

Fix any wrong value directly in the file, save, and restart the app ---
there is no need to reinstall. The one exception is an API key that no
longer works at all: generate a new one in Command Centre and paste that in.

\subsection{Finding the printer's COM port}\label{sec:comport}

\begin{wkwarn}[Device Manager is not the answer here]
The app writes \textbf{straight to the COM port} --- there is no printer
driver in between. The port the printer actually answers on does
\emph{not} always match what Device Manager shows against it, so read the
ports, then test them.
\end{wkwarn}

\paragraph{1. List the ports Windows can see.} In PowerShell:

\begin{lstlisting}
# Just the port names
[System.IO.Ports.SerialPort]::GetPortNames()

# ...with the device name against each, which narrows the field
Get-CimInstance Win32_PnPEntity |
  Where-Object { $_.Name -match 'COM\d+' } |
  Select-Object Name, DeviceID
\end{lstlisting}

Or, from Command Prompt, \wpath{mode} lists every COM device with its
current settings:

\begin{lstlisting}
mode
\end{lstlisting}

\paragraph{2. Test each port until the printer reacts.} Writing anything
to the right port makes the printer spit out a few lines of nonsense ---
that is the confirmation. Run this from \textbf{Command Prompt}, one port
at a time, working through the list from step 1:

\begin{lstlisting}
DIR > COM3
DIR > COM4
DIR > COM8
\end{lstlisting}

From PowerShell, hand the redirect to \wpath{cmd} instead, so it reaches
the device rather than creating a file:

\begin{lstlisting}
cmd /c "DIR > COM8"
\end{lstlisting}

How to read the result:

\begin{center}
\renewcommand{\arraystretch}{1.3}\small
\begin{tabularx}{\textwidth}{L{54mm} X}
\rowcolor{weknownight}\color{white}\textbf{What happens} &
\color{white}\textbf{Means}\\
Printer prints garbage &
That is the port. Note it and move to step 3.\\
\rowcolor{weknowgreyL}
Command returns silently, nothing prints &
The port exists but the printer is not on it. Try the next one.\\
\emph{Access is denied} &
Something already holds the port --- usually the kiosk app. Close it and
try again.\\
\rowcolor{weknowgreyL}
\emph{The system cannot find the path specified} &
No such port. Try the next one.\\
\end{tabularx}
\end{center}

\paragraph{3. Set the port in \wpath{kiosk-identity.json}.} There is
\textbf{no need to rerun the silent install}. Open
\wpath{kiosk-identity.json}, set the printer port to the one you
confirmed, save, then restart the app and print a test receipt.

\begin{wkinfo}[Note it on the installation record]
If the printer turned out to be on a non-standard port, put it in the
\textbf{Notes} field of the installation record. It saves the next
engineer repeating this.
\end{wkinfo}
